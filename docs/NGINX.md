# HTTPS reverse proxy Nginx — AWG31 Console

В тестовом выпуске **v0.5.0-test** мастер предложит три варианта:

| Выбор | Что происходит |
|---|---|
| `0` — без reverse proxy | Nginx **не устанавливается**; панель слушает только `127.0.0.1:8080` (или выбранный порт) |
| `1` — Nginx + самоподписанный сертификат | Устанавливает Nginx при необходимости; генерирует RSA-3072 TLS сертификат с SAN IPv4/DNS, действующий 365 дней |
| `2` — Nginx + свой сертификат | Спрашивает **абсолютные пути** к PEM сертификату/fullchain и к **незашифрованному** закрытому ключу, проверяет их соответствие и срок действия |

При выборе `1`/`2` мастер спрашивает домен или IPv4 (без `https://`), внешний TCP-порт HTTPS (по умолчанию `443`). Локальный порт FastAPI был указан ранее. **Nginx слушает только IPv4**, например `443/tcp`, и перенаправляет на `http://127.0.0.1:8080`. Приложение не связывается с `0.0.0.0` даже при отсутствии Nginx. Nginx, Squid, BIND и другие сервисы вне выбранного Nginx не устанавливаются.

**Самоподписанный сертификат** пригоден для тестирования и частной сети. Браузер покажет предупреждение о недоверенном издателе; корректный HTTPS без предупреждения требует сертификата доверенного центра или доверия к вашему CA. Установщик **не** выпускает Let's Encrypt автоматически (для этого нужны домен, публичная доступность и проверка владения доменом).

## Безопасность и существующий Nginx

- Сайт создаётся только в `/etc/nginx/conf.d/awg31-panel.conf`. Существующий файл с таким именем **никогда не перезаписывается**.
- Перед применением выполняется `nginx -t`, после применения — ещё одна проверка и HTTPS-healthcheck на localhost. Ошибка откатывает новый сайт, не трогая `awg0`, клиентов, ключи и FastAPI.
- При полностью отключённом IPv6 новый Nginx может иметь стандартный `listen [::]:80`. Установщик удаляет его **только из конфигурации только что установленного Nginx**, сохраняя резервную копию. Действующие конфиги уже установленного Nginx не меняются.
- При **SELinux Enforcing** на Rocky с Nginx нужен `httpd_can_network_connect=on`, о чём мастер предупреждает и требует подтверждения. Порт HTTPS на Rocky с Enforcing в этой тестовой версии — **443**. SELinux и firewalld не отключаются.
- Для активного UFW/firewalld скрипт **отдельно спросит**, разрешать ли входящий TCP-порт. Внешний firewall провайдера и NAT на роутере настраиваются отдельно.
- Сторонний сертификат и ключ остаются на указанных путях: установщик их **не копирует** и не меняет их права.

## Настроить Nginx после установки

Если в мастере выбрали `0`, конфигурацию можно добавить позже без переустановки VPN:

```bash
sudo awg31 nginx
```

Для ручной проверки:

```bash
sudo nginx -t
sudo systemctl status nginx --no-pager
curl --noproxy '*' -kfsS --resolve vpn.example.net:443:127.0.0.1 https://vpn.example.net/health
```

Для публичного FQDN замените домен в команде на ваш. Опция `-k` используется **только в тестовой проверке** и не отменяет необходимость доверенного сертификата в браузере. Проверьте ограничения доступа к администраторской панели (по IP/VPN), так как простой HTTPS не заменяет авторизацию, обновления безопасности и защиту от подбора пароля.

## Обновление

`sudo awg31 nginx` на уже установленной панели доступна после обновления контроллера с v0.5.0. Автоматические обновления UI/VPN и его ключей не затрагивают Nginx. Скрипт **не** запускает установку Nginx при `--upgrade` без явного выбора администратора.
