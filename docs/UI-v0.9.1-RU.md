# AmneziaWG Console v0.9.1-test

## Один sidebar вместо двух

В «Обслуживании» используются горизонтальные вкладки для диагностики, резервных копий, восстановления, профилей, безопасности, журнала и системы. Дополнительная левая навигация удалена; адреса `/maintenance?tab=...` сохранены.

## Графики обзора

`/api/overview/telemetry` требует авторизации. Каждые 5 секунд браузер считывает агрегированные RX/TX AWG, CPU/RAM и uptime сервера. Скорости и процент CPU рассчитываются из последовательных измерений. История линий живёт только во вкладке браузера. API не возвращает ключи клиентов.

## Генератор таймингов

В настройках сервера откройте обфускацию, отметьте «Генерировать тайминги AWG 3.1» и нажмите генерацию. Включение добавит RekeyAfterTime=112-118, RekeyTimeout=4-6, RejectAfterTime=176-184, KeepaliveTimeout=9-11, MaxHandshakeAttempts=8-12. Без галочки тайминги не меняются. Чтобы применить настройки, нужно отдельно нажать «Сохранить и перезапустить VPN». Смена S/H или HeaderProtectionKey требует перевыпуска конфигураций клиентов.

## Длинный I1/CPS

На странице конкретного клиента откройте «Дополнительные пакеты I1–I5». Вставьте длинное выражение `<b 0xHEX>` в многострочный редактор. По умолчанию CPS отключён и отсутствует в клиентском .conf. Ограничение: 16384 символа на поле, до 8192 байт суммарно после разворачивания CPS. Большие пакеты могут фрагментироваться на уровне UDP и потеряться. В случае слишком большого QR скачивайте .conf или копируйте текстовый vpn://. После изменения CPS клиенту нужен новый импорт конфигурации.

## Обновление

Сделайте snapshot VPS. Затем:

```bash
cd /root/awg31-update
git pull --ff-only origin main
sudo bash scripts/upgrade-core.sh </dev/null
sudo awg31 servers
curl -fsS http://127.0.0.1:8080/health
```

Скрипт не переустанавливает модуль ядра и не пересоздаёт awg0, но откат SQLite при ошибке не гарантирован. Проверки локальные; реальная передача большого CPS и тайминги на VPS не подтверждены.
