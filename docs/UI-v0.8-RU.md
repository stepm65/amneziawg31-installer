# AmneziaWG Console v0.8.0-test: разделение серверов и резервные копии

## Навигация

| Адрес | Что показывает |
|---|---|
| `/` | Обзор ВСЕХ AWG-серверов и состояния системы: ядро, модуль, DKMS, Secure Boot, IPv4 forwarding, панель |
| `/servers` | Список интерфейсов, создание и управление их состоянием |
| `/servers/awg0/overview` | Параметры только `awg0` |
| `/servers/awg0/clients` | Клиенты, маршруты, квоты, экспорт конфигураций только `awg0` |
| `/servers/awg0/monitoring` | Live-график и история `awg0` |
| `/servers/awg0/settings` | Параметры и обфускация только `awg0` |
| `/maintenance?tab=backups` | Архивы **всех** интерфейсов, расписание и удаление |
| `/maintenance?tab=restore` | Выбор и проверка конкретного архива, восстановление |
| `/maintenance?tab=profiles` | Экспорт и импорт настроек с **явным указанием интерфейса** |

Пример: после создания `awg1` выберите его в левом меню, откройте «Клиенты сервера». Вкладка `/servers/awg0/clients` останется привязанной к `awg0`, даже если во второй вкладке открыт `awg1`.

## Работа с резервными копиями

1. Создать вручную: **Обслуживание → Резервные копии → Создать**.
2. Для удаления выбрать кнопку **Удалить** рядом с конкретным архивом; удаление необратимо.
3. Для восстановления: **Обслуживание → Восстановление**, выбрать архив из выпадающего списка, при необходимости выполнить проверку целостности, ввести `ВОССТАНОВИТЬ` и подтвердить. Это временно прерывает VPN и панель. Автоматически создаётся защитная копия текущего состояния (механизм восстановления остаётся экспериментальным).
4. Для автоматического копирования: на странице «Резервные копии» указать ежедневно или раз в неделю, час и минуты в **UTC**, срок хранения 1–365 дней и максимальное число архивов 1–30. Сохранить. Таймер выполняется без открытого браузера.

**Важно о хранении:** автоочистка удаляет только файлы с именами собственного формата `awg31-...tar.gz` из выделенного каталога. Сначала создаётся новый архив, и только потом удаляются устаревшие. При выключенном расписании автоочистка не выполняется. Существующие архивы при обновлении не удаляются. Архивы содержат приватные ключи и парольные хеши и **не шифруются** дополнительно; храните их в защищённом месте.

Планировщик и политика хранения сохраняются локально в `/etc/awg31-panel/backup-policy.json`; текущий формат полного архива `awg31-backup-v1` не включает политику расписания. После восстановления на новый сервер её нужно настроить заново. Восстановление DKMS, Nginx и политик firewall также пока не входит в архив.

## Проверки на Ubuntu 26.04

```bash
cd /root/awg31-update
git pull --ff-only origin main
sudo bash scripts/upgrade-core.sh
sudo awg31 servers
sudo awg31 backup-policy
systemctl status awg31-panel --no-pager
systemctl list-timers awg31-backup.timer --all
journalctl -u awg31-backup.service -n 50 --no-pager
curl -fsS http://127.0.0.1:8080/health
```

`systemctl list-timers` покажет таймер только после включения расписания через панель. На новой версии нужные sudoers и systemd-файлы устанавливаются скриптом `upgrade-core.sh`; `upgrade-ui.sh` не предназначен для первого обновления до v0.8.

## Ограничения тестового выпуска

Маршруты на сервере и в интерфейсе проверены локальными тестами, но действия над двумя реальными AWG-интерфейсами, VPN-трафик и завершение systemd-восстановления ещё не проверены на вашем VPS. Перед испытанием восстановления сделайте snapshot VM.
