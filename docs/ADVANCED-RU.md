# AWG 3.1 — расширенные настройки и несколько интерфейсов (0.2.0-test)

> **Экспериментальная версия.** Сначала тестируйте на отдельном VPS и снимке VM. Система `awg0` уже работает у тестировщика Ubuntu 26.04.1, но создание дополнительного интерфейса `awg1` и применение обфускации пока не проверены на его сервере. Публикация как stable преждевременна.

## Что добавлено

- Список серверов `awg0`, `awg1`, `awg2`… (до 8 на один VPS), переключение серверов; запуск и остановка через systemd.
- Каждый сервер имеет свой интерфейс, конфигурацию `/etc/amnezia/amneziawg/awgN.conf`, SQLite-базу клиентов и ключи. Для `awg0` сохраняется **старый путь** `/var/lib/awg31-panel/state.sqlite3`, остальные базы в `/var/lib/awg31-panel/servers/awgN.sqlite3`.
- `server-create` проверяет уникальность имени, UDP-порта, пересечение VPN-подсетей друг с другом и с системными IPv4-маршрутами. Все новые интерфейсы имеют **только IPv4**; full tunnel (`0.0.0.0/0`) включён по умолчанию.
- В панели `Настройки сервера → Параметры обфускации AWG 3.1` доступны `Jc`, `Jmin`, `Jmax`, `S1`–`S4`, `H1`–`H4` (целые числа или диапазоны), `HeaderProtectionKey`, `ContentPaddingAddition`, `RandomTrailers`, `DisableCookies` и пять таймеров протокола. Есть кнопка **Сгенерировать параметры**.
- Все генерации используют `secrets` Python. Генератор возвращает случайный `HeaderProtectionKey` (32 байта в base64), четыре непересекающихся H-значения и S-паддинги (>=12), подходящие для AWG 3.1. Нажатие «Сгенерировать» **только заполняет поля**. Изменения происходят после отдельного сохранения.
- При сохранении настроек создаётся резервная копия прежних конфигурации и SQLite-базы в `/var/backups/awg31-panel/settings`. Если restart/syncconf заканчивается ошибкой, файл конфигурации восстанавливается; SQLite транзакция откатывается.
- Удаление второго сервера допускается только после удаления всех его клиентов и сохраняет backup. `awg0` из панели удалить нельзя.

## Установка поверх v0.1.x на тестовом VPS

Скопируйте ZIP в `/root` и выполните:

```bash
mkdir -p /root/awg31-v020
unzip amneziawg31-ubuntu-installer-v0.2.0-test.zip -d /root/awg31-v020
cd /root/awg31-v020/amneziawg31-ubuntu-installer
bash scripts/upgrade-core.sh
```

`upgrade-core.sh` делает backup **файлов приложения** (web, CSS/JS, controller, sudoers) до замены; изменяет разрешённые команды пользователя `awgpanel` на одну ограниченную CLI-точку `awg31mgr` и перезапускает только веб-службу. Этот скрипт **не останавливает `awg0`, не пересоздаёт ключи, не переписывает VPN-конфигурацию и не удаляет клиентов**.

Проверьте:

```bash
systemctl is-active awg31-panel
curl --noproxy '*' -4fsS http://127.0.0.1:8080/health
/usr/local/sbin/awg31mgr servers
runuser -u awgpanel -- sudo -n /usr/local/sbin/awg31mgr servers
awg show awg0
```

Если панель использует другой локальный порт, замените 8080. Текущий Nginx продолжает проксировать на localhost; внешние веб-порты не открываются.

## Проверка второго интерфейса

В веб-панели откройте **Серверы и интерфейсы → Создать сервер** и выберите:

- `awg1`
- `10.77.20.0/24` (если нет конфликтов с вашей сетью)
- UDP `51821` (при условии что свободен)
- MTU `1280`
- uplink `ens33` на тестовой машине
- Endpoint `10.10.20.29` для клиентов из той же LAN (для интернета — публичный IPv4/DNS и проброс UDP)
- Режим **Весь IPv4 через VPN**

После создания выполняйте:

```bash
systemctl status awg-quick@awg0 awg-quick@awg1 --no-pager
ip -4 addr show awg0
ip -4 addr show awg1
awg show all
/usr/local/sbin/awg31mgr servers
```

Создайте клиента в `awg1`, импортируйте `.conf` на устройстве с поддержкой AWG 3.1, проверьте handshake, DNS и интернет. Затем переключитесь обратно на `awg0` и убедитесь, что его клиенты и ключи не изменились.

## Согласованность параметров

`S1`–`S4`, `H1`–`H4`, `HeaderProtectionKey` и `RandomTrailers` должны согласовываться на клиенте и сервере. Генерируемый сервером клиентский конфиг содержит параметры текущего сервера. После изменения конфигурации **переимпортируйте новые профили всех клиентов этого интерфейса**, иначе они могут перестать соединяться. Для клиента с IPv6 адресом вне туннеля действуют отдельные ограничения, сервер не обслуживает IPv6.

`I1`–`I5` (пакеты-имитации, клиентская сторона) в этом релизе отдельно не редактируются; балансировщик между выходными серверами, GeoIP/маршрутизация Xray и сложные маршруты клиентов не реализованы — это другой уровень функциональности.

## Отладка

```bash
journalctl -u awg31-panel -n 100 --no-pager
journalctl -u awg-quick@awg1 -n 100 --no-pager
sudo awg show awg1
sudo iptables -t nat -S POSTROUTING
```

**Обратите внимание:** отдельные серверы пользуются одним публичным IPv4 и разными UDP-портами. Для доступа снаружи надо пробрасывать каждый порт, если VPS находится за NAT. Системный `net.ipv4.ip_forward=1` общий для всех серверов.
