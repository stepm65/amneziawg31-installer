# AWG Console v0.9.2-test — системный дашборд и экземпляры

## Новая структура общего обзора

Страница `/` теперь делится на два уровня. Сверху находятся **метрики Linux-хоста** (CPU, RAM, SWAP, DISK, внешний интерфейс WAN, TCP/UDP, время работы системы и память процесса панели). Ниже — отдельные карточки для каждого `awg0`, `awg1`, `awg2` и т. д., с индивидуальным графиком RX/TX, текущей скоростью, числом активных клиентов и собственными счётчиками. Никакой общей таблицы вместо графиков на главном экране нет.

В карточках AWG можно переключить интервал: 5 минут, 15 минут, 1 час. Управление клиентами и настройки открываются только по маршрутам `/servers/awgN/clients`, `/servers/awgN/settings`; операции запуска, остановки и перезапуска выполняются для конкретного экземпляра через меню `…`, с подтверждением. Нельзя менять сразу несколько серверов выбором общей cookie.

## Что именно измеряется

- **CPU:** дельта суммарных/idle-jiffies ядра `/proc/stat`, не придуманная нагрузка. График процентный.
- **RAM:** `(MemTotal - MemAvailable) / MemTotal` из `/proc/meminfo`.
- **SWAP:** `SwapTotal - SwapFree`; если swap отключён, показано 0% и «Не используется».
- **DISK:** занятое пространство корневой файловой системы `/` через `statvfs`. Не объём всех отдельных дисков.
- **WAN:** скорость RX/TX по интерфейсу IPv4-маршрута по умолчанию из `/proc/net/route` и счётчиков `/sys/class/net/…/statistics`. Это **общий WAN хоста**, а не сумма `awgN`, что исключает двойной учёт туннельного трафика.
- **Соединения:** установленные TCP-соединения и число UDP-сокетов из `/proc/net`. Не число VPN-клиентов.
- **По каждому AWG:** RX/TX из статистики peer этого **конкретного интерфейса**; после рестарта счётчиков значение может сброситься, но график не должен показывать отрицательные скорости. Онлайн — handshake за последние три минуты. Uptime — время активности службы `awg-quick@awgN` по systemd, если его удалось получить.

Все значения приходят из авторизованных API без приватных ключей. Пока нет измерений, вместо выдуманной линии показывается «Сбор данных…». Клиентские графики дополнены измерениями из существующей таблицы `traffic_samples`, системные — из новой таблицы `host_samples` в `state.sqlite3` (новая история начинается с первого запуска нового сэмплера). На графиках за 5/15/60 минут точность старой истории примерно 1 минута, текущая — по 5-секундным обновлениям браузера.

## Безопасное обновление установленной панели

Сделайте snapshot виртуальной машины, оставьте доступ к консоли VPS и выполните:

```bash
cd /root/awg31-update
git pull --ff-only origin main
sudo bash scripts/upgrade-core.sh </dev/null
sudo awg31 servers
sudo systemctl start awg31-sampler.service
systemctl is-active awg31-panel awg31-sampler.timer
curl -fsS http://127.0.0.1:8080/health
```

`sudo systemctl start awg31-sampler.service` создаёт первый системный срез и применяет существующие политики сроков/лимитов клиентов — выполняйте его только после проверки этих политик. При штатном использовании сэмплер запускается автоматически по таймеру.

Если веб-панель не запустилась, `upgrade-core.sh` возвращает прежние файлы кода. Обратите внимание: при сбое он **не откатывает автоматически SQLite**; для восстановления всей системы используйте snapshot или подтверждённый резервный архив из консоли.

После обновления обновите страницу браузера через Ctrl+Shift+R. Проверьте общий обзор, затем `awg0` и `awg1` отдельно. Если графики пустые — посмотрите `systemctl status awg31-sampler.timer` и `journalctl -u awg31-sampler.service -n 60 --no-pager`.

**Статус v0.9.2-test:** местные unit/API-тесты и Chromium подтверждают работу исходников и адаптивность, но подключение настоящих peer, рестарты и история на реальном VPS ещё требуют испытания. Скриншоты в документации/чате могут показывать специально обозначенные демонстрационные счётчики.
