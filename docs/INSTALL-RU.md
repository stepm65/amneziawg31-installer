> **Актуальное дополнение v0.5.0-test:** мастер теперь предлагает установку Nginx с самоподписанным сертификатом, Nginx с собственными PEM-файлами или установку без reverse proxy. Разделы ниже могут описывать прежние версии, см. [NGINX.md](NGINX.md).

> **Обновление v0.1.2-test:** скрипт использует предварительно установленный модуль ядра AmneziaWG 3.1 и amneziawg-tools 3.1; не добавляет PPA и не устанавливает их сам. Если в тексте ниже упоминается установка PPA установщиком, этот шаг устарел.

# Пошаговая установка и тестирование на Ubuntu 26.04

## 0. Важные условия

- Нужен отдельный тестовый VPS/сервер Ubuntu **26.04** x86_64 или ARM64, root через `sudo`.
- Запущенный kernel должен иметь headers (`linux-headers-$(uname -r)`), Secure Boot должен разрешать загрузку DKMS (или модуль должен быть подписан).
- Не ставьте на существующую VPN-инсталляцию: скрипт откажется, если уже есть `awg0` или база/конфиг.
- Желателен снимок виртуального диска и доступ к консоли провайдера. Скрипт устанавливает пакеты через APT, настраивает systemd и в режиме `full` IPv4 forwarding/NAT.
- **IPv6 может быть полностью выключен в ядре.** Настройки IPv6 не трогаем.
- Установщик **не** скачивает скрипты WireSock и не включает протокол 2.0.

## 1. Начальная проверка

```bash
cat /etc/os-release
uname -m
uname -r
ip -4 addr
ip -4 route
# Если модуль IPv6 отключён полностью, команда может показать ошибку — это нормально:
ls /proc/sys/net/ipv6 2>/dev/null || true
```

Если ядро обновилось до установки пакета DKMS, сначала перезагрузите VPS в новое ядро и проверьте headers. **Не перезагружайте при сломанной сборке DKMS:** сеть и VPN могут не подняться после смены ядра.

## 2. Перенос проекта

Скопируйте весь каталог `amneziawg31-ubuntu-installer` с вашего компьютера через SCP/SFTP. После публикации на GitHub можно использовать `git clone`.

```bash
cd amneziawg31-ubuntu-installer
bash -n install.sh
sudo bash install.sh
```

До появления публичного репозитория **не** используйте выдуманный `curl | bash` URL.

## 3. Вопросы установщика

| Вопрос | Пример | Значение |
|---|---|---|
| VPN-подсеть | `10.77.10.0/24` | только IPv4, /24…/29, без пересечения с сетью сервера |
| UDP-порт | `51820` | порт клиента `Endpoint` |
| MTU | `1280` | безопасное стартовое значение, допустимо 576…1420 |
| Endpoint | `vpn.example.net` | внешний IPv4 или DNS-имя без порта |
| DNS клиента | `1.1.1.1` | существующий IPv4 DNS; установщик DNS-сервер **не** ставит |
| Режим | `full` | **по умолчанию весь IPv4-трафик клиентов через VPN**; `split` — только VPN-подсеть |
| Внешний интерфейс | `ens3` | нужен для режима `full`, NAT через iptables |
| Веб-панель | `8080` | слушает строго `127.0.0.1` |
| Первый клиент | `test-client` или `skip` | латинские буквы, цифры, `-`/`_`; `skip` — пропустить |
| Пароль панели | ввод скрыт | минимум 12 символов |

Важно: **рекомендуемый режим по умолчанию — `full`**. Для него перед запуском интерфейса включается IPv4 forwarding и устанавливаются симметричные правила `FORWARD` (исходящие и установленные ответные соединения), а также `MASQUERADE` через выбранный внешний интерфейс. Для `split` не делаем IP-forwarding/NAT; доступ клиентов к сервисам, слушающим VPN-адрес самого сервера, работает после открытия нужных портов в серверном firewall. Для доступа к другим узлам/клиентам понадобится дополнительная IPv4-маршрутизация.

## 4. Что устанавливается

1. APT-зависимости, текущие linux headers, `dkms`.
2. Проверка заранее установленного DKMS-модуля и утилит AmneziaWG 3.1 (без PPA).
3. Проверка `modprobe amneziawg` и версии модуля `3.1.x`.
4. Генерация профиля **3.1 сразу**: HeaderProtectionKey, S1…S4=12, H1…H4=1…4, RandomTrailers и DisableCookies `on`.
5. `awg0` через `awg-quick@awg0.service`.
6. Клиентские ключи и конфиги через локальную SQLite.
7. Веб-панель FastAPI, systemd, пользователь `awgpanel` и ограниченные sudo-команды.

Если модуль версии `3.x` не построился, установка прерывается; **отката на 2.0 нет**. Обход проблемы kernel `7.0.0-38` намеренно не вшит до проверки на реальном сервере.

## 5. Проверка после установки

```bash
sudo lsmod | grep amneziawg
sudo modinfo amneziawg | grep -E 'filename|version'
sudo awg show awg0
ip -4 addr show dev awg0
sudo systemctl status awg-quick@awg0 --no-pager
sudo systemctl status awg31-panel --no-pager
curl -4fsS http://127.0.0.1:8080/health
sudo /usr/local/sbin/awg31ctl status
sudo /usr/local/sbin/awg31ctl list
```

Не печатайте `/etc/amnezia/amneziawg/awg0.conf` или базу SQLite в публичные логи/Issue: содержат приватные ключи.

## 6. Firewall и клиент

Проверьте, что UDP-порт из мастера открыт в **firewall сервера и провайдера**. Скрипт намеренно не изменяет действующие UFW/nftables правила, чтобы не потерять SSH. Для управления портом провайдера используйте консоль его панели.

Откройте веб-панель через свой Nginx с TLS (см. [NGINX.md](NGINX.md)), авторизуйтесь, создайте клиента или откройте первого. Скачайте `.conf` или QR. Клиентское приложение должно поддерживать AmneziaWG 3.1. Попробуйте соединиться и обратиться к `10.77.10.1` (или вашему внутреннему VPN-адресу); для ping необходим ICMP allow в firewall сервера.

Сценарий теста: проверить handshake в `sudo awg show awg0`, затем доступ к существующему TCP-сервису, самостоятельно привязанному к VPN IP (установщик не ставит ни DNS, ни proxy).

Проверка полного IPv4-туннеля: после подключения клиента выполните на нём `curl -4 https://api.ipify.org` — ожидается публичный IPv4 VPN-сервера (при отсутствии дополнительных маршрутов/NAT у провайдера). Сравните со значением до подключения. Команда `ip route` на клиенте должна показывать маршрут IPv4 по умолчанию через VPN.

**IPv6:** конфигурация намеренно не содержит `::/0` и не создаёт IPv6 firewall. Если на клиенте включён IPv6, он может ходить в интернет напрямую вне VPN. Для предотвращения утечек настройте политику IPv6 на клиентском устройстве самостоятельно.

## 7. Веб-панель

Веб-интерфейс доступен только через `127.0.0.1:PORT`; Nginx/HTTPS не устанавливается. Пароль задан при установке. Куки помечены `Secure`; через обычный HTTP после входа браузер сессию не сохранит — это ожидаемо. Используйте HTTPS reverse proxy.

Из панели можно менять endpoint, UDP-порт, MTU, DNS. Эти изменения требуют повторного импорта клиентских `.conf`. Изменение subnet/full/split через панель не поддерживается в тестовой версии.

## 8. Типичные ошибки

**`modprobe: FATAL: Module amneziawg not found`** — DKMS не собрал модуль для `uname -r`. Посмотрите `dkms status`, `modinfo amneziawg`, `/var/lib/dkms/amneziawg/*/build/make.log` и `journalctl -u dkms`.

**`setup_udp_tunnel_sock`** — известная несовместимость некоторых сборок на Ubuntu 26.04 `7.0.0-38`. Установщик не исправляет драйвер автоматически. Для тестирования используйте проверенное совместимое ядро или дождитесь патча от upstream. Не меняйте ядро вслепую по SSH.

**`awg-quick@awg0` не запущен** — `sudo journalctl -u awg-quick@awg0 -n 100 --no-pager`. Возможна несовместимость параметров 3.1, конфликт порта или firewall.

**Нет handshake** — проверьте адрес/порт, ключи, поддержку AWG 3.1 на клиенте и UDP-доступ. На обеих сторонах должны совпасть `S1…S4`, `H1…H4` и `HeaderProtectionKey`.

**Клиенты есть, но нет доступа к интернету** — в режиме по умолчанию (`full`) проверьте `sysctl net.ipv4.ip_forward`, счётчики `iptables -nvL FORWARD` и `iptables -t nat -nvL POSTROUTING`, наличие IPv4-маршрута через uplink и правила внешнего firewall. Если вручную выбран `split`, интернет-трафик не идёт через VPN.

**После смены порта нет соединения** — скачать новые клиентские конфигурации и открыть новый UDP-порт.

**Панель доступна локально, но не через Nginx** — проверьте TLS, `proxy_pass`, имя сервера и firewall Nginx.

## 9. Бэкапы для тестового развёртывания

В бэкап обязательно включать оба файла: `/etc/amnezia/amneziawg/awg0.conf` и `/var/lib/awg31-panel/state.sqlite3`, плюс `/etc/awg31-panel/auth.json`. Бэкап хранить зашифрованным, доступным только администратору.

Перед переустановкой храните копии вне VPS. Команды удаления для тестового выпуска не автоматизированы: штатный uninstall будет добавлен после серверного теста.


## Восстановление после ошибки sudoers в v0.1.2-test

Если установка успела создать `awg0`, базу SQLite, пароль администратора и остановилась на `Defaults:awgpanel !requiretty`, **не перезапускайте** `install.sh`: это приведёт к отказу защиты от перезаписи.

Из обновлённого проекта запустите от root:

```bash
cd /root/amneziawg31-ubuntu-installer
bash scripts/resume-panel.sh
```

Скрипт спрашивает **порт веб-панели** (укажите тот же, что вводили в мастере), удаляет неподдерживаемую директиву `requiretty`, проверяет sudoers, завершает создание systemd-службы и проверяет `/health`. Он не трогает `awg0`, приватные ключи и базу клиентов.
