# Что делать, если…

Короткие рецепты для частых неприятностей. Все команды — на самом сервере от root (`sudo`). English: [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

Если ничего не помогло, соберите **отчёт для поддержки** («Обслуживание → Журналы → Отчёт для поддержки»): ключи, токены и публичные адреса в нём заменены, но просмотрите его перед отправкой.

## Панель не открывается

1. `sudo awg31 status` — работают ли панель и серверы VPN.
2. `sudo awg31 restart-panel` — перезапустить только панель (VPN не затрагивается), затем `sudo awg31 logs` — её журнал.
3. Панель слушает только `127.0.0.1`. Без HTTPS заходите через SSH-туннель: `ssh -L 8080:127.0.0.1:8080 root@СЕРВЕР`, затем `http://localhost:8080` (подставьте свой порт панели).
4. Порт занят другой программой — `sudo awg31 port НОВЫЙ_ПОРТ`.
5. Нужен доступ по HTTPS — `sudo awg31 nginx`. Если у сайта задан список разрешённых адресов, проверьте, что ваш адрес в нём.

## Забыли пароль или имя для входа

`sudo awg31 reset-password` показывает имя главной учётной записи, позволяет его сменить и задаёт новый пароль. Все открытые сессии после этого завершаются.

Пароль другой учётной записи меняет администратор: «Обслуживание → Учётные записи → Изменить».

## Потерян телефон с двухфакторным входом

- На странице входа вместо кода из приложения введите один из **резервных кодов** (вида `XXXXX-XXXXX`), выданных при включении. Каждый код действует один раз. Новые коды — «Обслуживание → Безопасность».
- Если резервных кодов нет: `sudo awg31 totp-off` выключает двухфакторный вход главной учётной записи. Потом включите его заново с новым телефоном.
- Двухфакторный вход другой учётной записи из консоли не выключается: администратор удаляет эту учётную запись и создаёт её заново.

## Потерян ключ доступа (passkey)

Войдите по паролю (и коду, если включён) и удалите потерянный ключ в «Обслуживание → Безопасность → Ключи доступа». Пароль от ключей доступа не зависит и продолжает работать.

## После обновления ядра VPN не поднялся

Модуль AmneziaWG собирается через DKMS отдельно для каждого ядра. Консоль сама проверяет новое ядро несколько раз в день и предупреждает в панели и в боте ещё до перезагрузки.

1. `sudo awg31 doctor` — проверка ядра, DKMS и интерфейса; DKMS пересоберёт модуль, если есть заголовки нового ядра.
2. Заголовков нет — установите их и повторите `doctor`:
   - Ubuntu/Debian: `apt install linux-headers-$(uname -r)`
   - Rocky/Alma: `dnf install kernel-devel-$(uname -r)`
3. Включён Secure Boot — после перезагрузки зарегистрируйте ключ DKMS (MOK) из консоли сервера, как при установке.
4. Временно можно загрузиться со старым ядром из меню загрузчика.

## Клиенты не подключаются

1. `sudo awg31 status` — сервер запущен?
2. UDP-порт сервера открыт и в облачном файрволе провайдера, а не только в ufw или firewalld.
3. Кнопка «Проверить входящие пакеты (15 с)» на странице сервера (в боте — «📡 Пакеты 15 с») 15 секунд слушает порт. Если пакетов нет, их режут по пути — это файрвол или блокировка, а не настройки клиента.
4. «Обслуживание → Журналы → Отладка рукопожатий» на 15 минут показывает, что модуль ядра думает о попытках подключения.
5. Клиент помечен «Нужна новая конфигурация» — настройки сервера менялись, выдайте конфигурацию заново (бот присылает её владельцам сам, если им это разрешено).
6. Соединение есть, но сайты не открываются — уменьшите MTU (например, до 1200) или включите clamp MSS в настройках сервера.

## Заблокировали порт или протокол

- Сигнал о блокировке (все клиенты пропали сразу) приходит в панель и бот. По желанию сервер сам меняет порт.
- «Настройки сервера → Маскировка и смена параметров»: профиль маскировки (QUIC, STUN, DTLS, DNS, Steam) или «Сменить сейчас» — новый порт и обфускация.
- После смены бот сам присылает владельцам новые конфигурации, а роутеры с подпиской забирают их сами. Остальным клиентам выдайте конфигурации заново.

## Заблокировали IP сервера: переезд на новый сервер

1. На старом сервере (если он доступен) сделайте свежую копию: `sudo awg31 backup`. Если старый сервер недоступен, возьмите последнюю копию из внешнего хранилища (S3/SFTP) или скачанную из панели.
2. На новом сервере установите консоль той же или новее версии.
3. Положите архив в `/var/backups/awg31-panel/full/`. Зашифрованной копии нужен её пароль: `sudo awg31 backup-encryption on`.
4. `sudo awg31 restore-check ИМЯ`, затем `sudo awg31 restore ИМЯ`.
5. Укажите новый адрес в настройках сервера (поле Endpoint). Если клиенты подключаются по домену, достаточно поправить A-запись домена: конфигурации менять не нужно.
6. Бот пришлёт владельцам новые конфигурации, где это разрешено. Можно ещё отправить «Сообщение владельцам» с кнопкой «Мои подключения».

Чтобы переезд был быстрым, заранее включите шифрование и внешнее хранилище копий (`backup-encryption on`, `backup-remote s3|sftp`) и проверку копий по расписанию.

## Обновление не удалось

- Если обновление сломалось на середине, программа сама возвращается из снимка.
- `sudo awg31 rollback` возвращает версию до последнего обновления, `sudo awg31 rollback list` показывает снимки. Данные (клиенты, серверы, настройки) откат не трогает.
- Повторить обновление: `sudo awg31 update` или указать версию: `sudo awg31 update vX.Y.Z`.

## Резервная копия не проходит проверку

- `sudo awg31 backup-verify` — подробная причина.
- «Cannot decrypt» — копия зашифрована другим паролем. После `sudo awg31 backup-encryption change` старые архивы перешифровываются; копию с другого сервера расшифруйте его паролем.
- «Remote storage is missing/mismatch» — копия не дошла до хранилища или повреждена там. Проверьте хранилище: `sudo awg31 backup-remote test`, затем сделайте новую копию.

## Бот не отвечает

1. `sudo awg31 telegram status` — служба работает, токен принят?
2. `sudo awg31 telegram test` — пробное сообщение администраторам.
3. Если токен в BotFather перевыпускали, подключите бота заново: `sudo awg31 telegram`.
4. Бот отвечает только администраторам, наблюдателям и владельцам клиентов (и незнакомым — если включены запросы доступа). Каждый должен один раз нажать **Start**.
5. Журнал бота — в «Обслуживание → Журналы» (источник «Telegram-бот»).

## Заканчивается место на диске

- `sudo awg31 db-vacuum` — сжать базы; срок хранения истории трафика уменьшается в «Обслуживание → Журналы».
- Резервные копии: срок хранения и количество — в расписании копий; лишние можно удалить: `sudo awg31 backup-delete ИМЯ`.
- Снимки обновлений (`/var/backups/awg31-upgrade.*`): `sudo awg31 rollback delete ИМЯ`.
- Системный журнал: `journalctl --vacuum-size=200M`.

## Установка прервалась

Если ничего ещё не создано, запустите установщик снова. Если VPN уже создан, завершите настройку: `sudo bash amneziawg31-installer/scripts/resume-panel.sh` из клона репозитория. Начать с нуля: установщик с `--uninstall --purge`. Подробно — в README, раздел «Прерванная установка».
