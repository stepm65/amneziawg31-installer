# Восстановление полной резервной копии (v0.6.1-test)

Восстанавливает архив `awg31-backup-v1`, созданный функцией **Создать резервную копию** версии v0.6.0 или новее.
Это **не** восстановление старых snapshot-каталогов `/var/backups/awg31-v0.2.*`.

## Веб-панель

1. Откройте **Обслуживание и безопасность → Резервные копии**.
2. Найдите архив в списке. Если вы сохранили копию только на другом компьютере, перенесите её на сервер в `/var/backups/awg31-panel/full/` как root, с режимом `0600` и без изменения имени. Загрузка произвольного архива из браузера намеренно не предусмотрена.
3. Скопируйте важные новые конфигурации клиентов, созданные после момента резервной копии: после восстановления они исчезнут.
4. Введите `ВОССТАНОВИТЬ` (либо `RESTORE` для английского интерфейса) и нажмите **Восстановить**.
5. Проверка архива запускается до операции. Затем отдельная служба systemd через 5 секунд создаёт аварийную копию текущего состояния, останавливает сервисы, восстанавливает файлы и запускает службы, которые работали перед восстановлением.
6. Убедитесь, что VPN снова поднялся, и проверьте клиентов и авторизацию.

Восстановление **перезаписывает** ключи, настройки, SQLite клиентов и авторизацию. Текущие подключённые клиенты на время восстановления отключатся. После восстановления выдайте актуальные конфигурации, если ключи менялись. Не выполняйте на сервере без доступа к консоли или резервного SSH-доступа.

Логи планировщика: `systemctl list-units 'awg31-restore*' --all` и `journalctl -u 'awg31-restore-*' -n 100 --no-pager`.

## CLI

```bash
sudo awg31 backups
sudo awg31 restore-check awg31-YYYYMMDDTHHMMSSZ-xxxxxxxxxx.tar.gz
sudo awg31 restore awg31-YYYYMMDDTHHMMSSZ-xxxxxxxxxx.tar.gz
```

## Встроенные проверки

- Имя архива проверяется по строго заданному формату; пути выбирает сервер, а не браузер.
- Архив не распаковывается напрямую на файловую систему.
- Отклоняются символические ссылки, неизвестные пути, дубликаты, слишком крупные файлы и архивы с ошибками SHA256.
- Каждая SQLite-база проверяется `PRAGMA integrity_check` и наличием необходимых таблиц.
- Если архив не содержит один из уже существующих интерфейсов, восстановление отклоняется во избежание незаметного удаления серверов.
- Перед заменой создаётся дополнительная полная копия текущих данных.
- При сбое применения предусмотрена попытка возврата предыдущих файлов и повторного запуска служб.

## Ограничения v0.6.1-test

Это тестовая реализация; проведение полного цикла на реальном VPS ещё не подтверждено. Архив не содержит пакеты ОС, сам модуль DKMS, пользовательские настройки Nginx/SSL, правила стороннего файрвола и системы маршрутизации. Для миграции между машинами сначала установите совместимую версию приложения и модуля ядра. Полный откат состояния сетевого экрана не гарантируется.

Рекомендуется snapshot VPS перед первым испытанием восстановления.
